# 旅行决策与行程编排

把约束转成可执行的住宿、通勤或旅行方案。先保护固定时间和硬约束，只核验最终候选；将事实、建议和未知项分开表达。

## 适用场景

- 查询或比较住宿、酒店价格、库存、房型、位置、通勤和 OTA 候选。
- 规划机场、车站、酒店、会议地、景点之间的步行、骑行、驾车或公共交通。
- 生成单日或多日、按上午/下午/晚上或具体时间段组织的完整旅行行程。
- 查询目的地、景点、周边、天气，以及需要当前开放、预约、门票、临时关闭或活动信息的旅行任务。

## 不适用场景

- 与旅行或出行无关的写作、翻译或闲聊。
- 只需回答用户已经提供的旅行文本，不需要查询、比较或规划。
- 不把 OTA 跳转解释为代订、锁价、付款或成交；当前能力只提供预订前决策支持。

## 决策规则

- 先判断范围：单个地点、天气或路线只做快速查询；酒店请求做住宿决策；多个日期或活动需要按天安排时才做完整规划。
- 将日期、抵离时间、固定活动、人数、房间数、入住配置、预算上限、必须到访、无障碍和最晚到达视为硬约束；风格、景观和热闹程度属于软偏好。床型、加床或房间数组合会改变库存或报价时先澄清；其他信息只在缺失会阻止查询或明显改变方案时澄清。
- 酒店价格、库存和 OTA 链接只使用 `lodging_search` 的本轮结果。保留 `nightly_price`、`total_price`、`price_basis` 和 Provider 提示的口径，不自行改写成含税价、最终成交价或总预算。
- 地点发现和消歧使用文本或周边搜索；区域或广域景区不是唯一落点时，选择明确入口或交通节点并说明。路线工具缺经纬度时才做地理编码。`nearby_poi` 只是住宿偏好，严格步行、通勤或半径要求必须对最终酒店候选另行核验。
- 当前开放、预约、票务、临时关闭、活动和交通管制优先使用运营主体或官方来源。Provider-native 联网搜索不是本地 Tool；没有可识别来源或适用日期的结果只能作为攻略性建议或待确认事项。
- 未来若目录暴露专门的旅游内容或官方信息搜索工具，官方工具优先核验运营事实，内容工具只支持玩法、体验、拥挤和避坑建议；未暴露时继续使用 Provider-native 搜索，不调用或虚构不存在的工具。
- 完整规划先固定航班、火车、会议、演出和预约，再按相邻区域聚类活动。只核验准备采用的候选；路线没有未来出发时间语义时，只称为当前规划参考。
- 为进出站、安检、排队、找路、换乘、用餐和同行者体力保留可见缓冲。全部要求排不下时明确冲突并建议删减，不压缩缓冲伪造可行性。
- 天气工具未覆盖旅行日期时，不用相邻日期或气候均值冒充预报；标记出发前复查时间并准备室内外替代。

## 信息来源速查

| 需要回答的事实 | 首选来源 | 能支持的结论 |
| --- | --- | --- |
| 指定日期酒店价格、库存、OTA 链接 | `lodging_search` | 候选与工具实际返回的报价口径、跳转入口 |
| 地点名称、类型、地址、坐标、周边 | 地图地点或周边搜索 | POI 识别、区域和空间关系 |
| 步行、骑行、驾车、公共交通 | 对应路线工具 | 工具支持时间语义下的路线参考 |
| 旅行日短期天气 | 天气工具 | 返回项明确覆盖日期的预报 |
| 开放、预约、票务、临时公告 | Provider-native 搜索中的官方来源 | 与来源适用日期匹配的当前运营事实 |
| 游玩时长、体验、拥挤和避坑 | 攻略、OTA、UGC | 攻略性建议，不是官方承诺 |

## 执行流程

1. 提取目的地、日期、抵离、人数、房间与入住配置、预算口径、固定活动、交通偏好、节奏、兴趣和特殊需求；确定查询范围。
2. 需要住宿时先搜索真实日期候选，应用硬约束缩小范围，再核验最终候选到车站、机场或核心活动的关键通勤。
3. 需要完整行程时先放置抵离、入住退房、寄存和预约，再发现活动候选，并按区域分配到各日。
4. 按来源类型补证：酒店报价查住宿工具，地点和路线查地图，当前运营事实查官方信息，体验与玩法查内容来源，旅行日天气查天气工具。
5. 为每天的时间块加入移动、用餐、休息和缓冲；老人、儿童、慢节奏或无障碍场景降低密度。用路线证据检查关键相邻安排。
6. 若工具或搜索失败，继续完成不依赖它的部分，将失败项列为待确认。最后检查硬约束、时间冲突、候选对应关系、来源状态和 URL 来源后回答。

## 输出契约

- 快速查询只回答相关目标；住宿比较或完整规划才使用下面的对应结构。
- **方案摘要**：首选方案、主要取舍和没有满足的约束。
- **关键假设**：只列会影响价格、时间或可行性的假设。
- **住宿比较**：候选、每晚价、总价口径、位置与关键通勤、优缺点、对应 OTA 链接。没有 `booking_url` 时明确无可用跳转，不创建搜索链接或酒店详情 URL。
- **每日行程**：按日期和时间段列活动、地点、交通方式、预计移动时间、缓冲及核验状态；抵达日和返程日不得按完整游玩日塞满。
- **信息状态**：将内容标为“已核验信息”“攻略性建议”或“待确认事项”。时间敏感事实在来源可用时附官方或原生搜索返回的链接。
- **下一步**：列出需要用户在 OTA 或官方渠道自行完成的查看、预约或购买操作，不声称已经代为完成。

## 常见错误

- 不在工具或搜索尚未返回时预写具体酒店、价格、开放时间、路线耗时、天气或 URL。
- 不把地图酒店 POI 当成指定日期的房价和库存，也不把酒店描述中的“附近”当成严格通勤证据。
- 不从常识拼出 OTA 链接；只交付 `lodging_search` 本轮返回的 `booking_url`。
- 不照搬单篇攻略的现成行程；先应用用户硬约束、地理聚类、路线时间和体力节奏。
- 不把 UGC 的排队、好玩或推荐时长写成官方承诺，也不把缺少来源的搜索摘要写成当前规则。
- 不为了覆盖更多景点牺牲固定时间、交通缓冲、用餐和休息。不能全部容纳时明确建议删减。

## 完成前检查

- 任务模式正确：单点问题没有过度规划，完整旅行请求包含按天、按时间段的安排。
- 所有硬约束都已满足，或逐项说明冲突和最接近的替代方案；软偏好的取舍理由清楚。
- 酒店候选来自日期搜索，价格口径未被改写，严格位置或通勤要求已对实际候选核验。
- 每个相邻时间块在地理和时间上可行，抵离、入住退房、固定活动、用餐、休息和缓冲没有互相冲突。
- 当前开放、预约、票务和临时变更有适用日期与可识别来源；否则明确属于攻略性建议或待确认事项。
- 天气只使用覆盖旅行日期的预报；路线只按工具实际支持的时间语义描述。
- OTA 链接与候选一一对应；链接不代表锁价、库存保证、预订成功或最终成交。
