## 当前权威规则

本文件是面试训练模式、题库目录结构和文档更新规则的当前权威入口。涉及模拟面试、题目分级、回答点评、标准答案、面试金句或 `docs/interview/` 文档更新时，以本文件为准。

---

## 交互模式

默认采用模拟面试模式：

1. Codex 担任技术面试官，围绕指定模块出题。
2. 题目按重要程度分级：
   - 🔴 必考题：高频核心问题，要求能完整讲清楚。
   - 🟡 高频题：常见追问，要求能结合项目说明。
   - 🟢 加分题：答好可以拉开差距，通常涉及权衡、边界和工程细节。
3. 用户先回答。回答可以不完整，先暴露理解状态。
4. Codex 再反馈：
   - 先点评答对的部分。
   - 再指出不足、遗漏或表述风险。
   - 给出完整标准答案和深度解释。
   - 补充面试金句、加分技巧和本项目代码位置。

用户说“继续”时，Codex 默认出下一题；用户可以随时要求暂停、追问、换模块、换难度，或改成直接讲解模式。

## 文档目录结构

每个模块单独维护一个目录：

```text
docs/interview/
├── README.md
├── {module_name}_interview/
│   ├── index.md
│   ├── cheat-sheet.md
│   └── details/
│       ├── 01-xxxx.md
│       ├── 02-xxxx.md
│       └── ...
```

命名规则：

- 模块目录使用小写 snake_case，例如 `context_engineering_interview/`、`tool_calling_interview/`。
- detail 文件使用两位序号加短 slug，例如 `01-context-budget.md`。
- 一个问题只对应一个 detail 文档；后续追问可以追加到同一文档的补充小节。

## 详情文档结构

每题详情文档按固定结构保存：

```markdown
# 模块名 - 题目名

---

## 🔴/🟡/🟢 原题

完整题目描述。

---

## 我的回答

原样记录用户当时的回答。

---

## 面试官点评

答对的部分：
- ...

不足的地方：
- ...

---

## 标准答案

完整、可面试复述的答案。必要时包含表格、流程图、伪代码、代码片段和工程权衡。

---

## 面试金句

> 一到两句可以直接背诵的总结。

---

## 本项目代码位置

- `src/...`: 对应实现点。
- `tests/...`: 对应验证点。
```

标准答案必须优先保证正确性和可解释性；如果用户回答中有危险误解，要明确指出并给出正确表达。

## 模块索引结构

每个模块的 `index.md` 保存题目进度和摘要：

```markdown
# 模块名面试题库

---

## 模块覆盖进度

- [x] 一、xxx 篇
- [ ] 二、xxx 篇

---

## 一、xxx 篇

### Q1. 题目名 🔴/🟡/🟢

我的回答：
> 用户回答摘要。

核心考点：
- ...

[详情解答](details/01-xxxx.md)
```

`cheat-sheet.md` 保存面试前快速复习内容，只放关键词、核心链路、常见追问和面试金句，不放长篇解释。

## 自动更新规则

每题完成反馈后，如果正在进行面试题库维护，Codex 应同步更新：

1. 模块 `index.md`：追加题目、用户回答摘要、核心考点和详情链接。
2. 模块 `details/xx-xxxx.md`：记录原题、用户回答、点评、标准答案、金句和代码位置。
3. 模块 `cheat-sheet.md`：追加高密度关键词、核心链路和面试金句。
4. 本 README 的模块总览：必要时更新题目数和状态。

用户不需要额外说“更新文档”。如果用户明确要求只问答、不落文档，则以用户当前约束为准。

---

## 维护边界

- 面试材料是解释和训练资料，不是架构权威。涉及真实设计判断时，应回到对应专项权威文档，例如 context、tool calling、memory、agent communication。
- 不把 `docs/development/**` 当作当前面试答案来源，除非用户明确要求追溯历史。
- 新增面试模块时，优先复用上述目录结构，不新增额外总索引。
- 代码位置必须指向当前仓库真实文件；不确定时先搜索源码和测试。
