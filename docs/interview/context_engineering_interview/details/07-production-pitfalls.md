# 六、生产环境踩坑篇 - 详情

---

## 🟡 原题

线上用户反馈：刚才明明跟 Agent 说过"我的预算是 500 以内"，聊了 3 轮工具调用后，Agent 突然问"你的预算是多少来着？"

查日志发现：因为上下文膨胀，第 2 轮的用户输入"我的预算是 500 以内"被裁剪掉了，但 LLM 完全没意识到信息丢了，反而以为用户没说过。

请回答：
1. 这种问题的根因是什么？为什么 LLM 不知道信息被裁掉了？
2. 有哪些工程手段可以缓解这个问题？至少说 3 种
3. 怎么让 LLM 在发现信息缺失时主动追问，而不是瞎编或者假装用户没说过？

---

## Q1. 上下文裁剪后 LLM "失忆"问题 🟡

### 【我的回答】

### 【标准答案】

#### 1. 根因分析

这不是 LLM 傻，而是**系统设计的缺陷**——我们只做了"单向裁剪"，没有做"裁剪通知"。

| 层面 | 具体问题 |
|-----|---------|
| **信息层** | LLM 看到的 prompt 里，用户输入"我的预算是 500"直接消失了，没有任何标记说"这里之前有内容" |
| **提示词层** | System Prompt 里从来没告诉过 LLM："你的上下文是可能被裁剪的，如果发现信息断层，请追问" |
| **架构层** | 我们假设"裁剪掉的都是不重要的"，但这个假设不一定成立——系统觉得不重要 ≠ LLM 决策时不需要 |

**一句话根因**：
> 裁剪是"暗箱操作"，LLM 对裁剪这件事本身没有感知，也没有被告知如何处理信息缺失的情况。

---

#### 2. 5 种工程缓解手段

| 手段 | 具体做法 | 效果 | 成本 |
|-----|---------|------|------|
| **✅ 裁剪标记法** | 不是直接删掉，而是替换成：`[上下文裁剪：此处省略了 3 条较早的对话记录，如果需要请用户补充]` | 立竿见影 | 极低 |
| **✅ 不可裁剪区** | 用户直接输入的内容标记为 `[DO_NOT_TRIM]`，除非超 95% 预算否则不删；工具观察可以狠裁 | 用户体验大幅提升 | 低 |
| **✅ 滚动摘要保留** | 裁剪掉的对话不是直接删，而是压缩成 1 句话摘要保留，比如：`[之前对话摘要：用户预算 500，想要降噪耳机]` | 信息损失最小 | 中 |
| **✅ 分栏上下文注入** | prompt 里明确分块：<br>`===== 最近 2 轮完整对话 =====`<br>`===== 较早对话摘要（可能不全）=====`<br>让 LLM 知道哪部分可能有缺漏 | 最清晰 | 中 |
| **✅ 预算水位线标记** | prompt 最后加一句：`[当前上下文使用率 82%，已启用裁剪模式，部分历史可能省略]` | 心理预期管理 | 极低 |

---

#### 3. 让 LLM 主动追问的系统设计

这是面试加分项，核心是**"提示词工程 + 输出格式约束"双管齐下**：

##### 第一步：System Prompt 明确规则

```
===== 上下文完整性约定 =====

1. 你的上下文可能因为长度限制被裁剪，这是正常现象
2. 如果发现关键信息缺失、上下文断层、逻辑不连贯，请直接追问用户
3. 追问格式必须以 `[信息缺失请补充]` 开头
4. 绝对不要猜测用户没说过的信息，绝对不要"以为"用户说过什么
5. 拿不准的时候，与其猜，不如问
```

##### 第二步：System Prompt 行为约束（不是事后拦截）

**从源头禁止错误行为**

在 System Prompt 里明确写：
```
===== 行为约束：绝对不要做这些事 =====

❌ 绝对不要说："你之前说过..."、"我记得你说过..."
✅ 如果你确实在上下文里看到了，可以说："根据我们之前的对话..."
❌ 如果你在上下文里没看到，但是隐约觉得有，绝对不要猜
✅ 直接说："抱歉，我这边没看到相关信息，可以再说一遍吗？"
```

*可以加辅助校验（不拦截，只打日志）：检测到疑似幻觉关键词时，离线记录下来，用于后续优化裁剪策略。*

##### 第三步：裁剪关键词指纹 + 上下文提示

✅ **简单的关键词提示就够了**

**裁剪时记录关键词指纹**：不要直接删了就完事，提取被裁掉内容的前 3 个关键词：
```python
# 裁剪某轮对话时
trimmed_text, keywords = trim_with_keywords(old_turn, max_chars)
# keywords = ["预算", "500", "降噪"]
budget_report.trimmed_keywords.append(keywords)
```

**渲染 prompt 时给提示**：如果确实有内容被裁掉了，在 prompt 最后加一行：
```
...（正常上下文）...

[小提示：之前有 2 轮对话因为长度限制被裁剪了，涉及关键词：预算、降噪、商品价格。如果用户问起这些话题，可以让用户再补充一下]
```

**效果**：LLM 看到这句话后，就不会"以为用户说过"了——它会知道这些话题之前可能聊过，但自己没看到，应该让用户再说一遍。不需要写复杂的校验逻辑，LLM 自己会处理。

---

**面试金句**：
> 裁剪的本质不是"删"，而是"降级"。好的裁剪系统不是让用户感觉不到被裁，而是让用户在信息缺失时能被温柔地提醒，而不是让 AI 看起来突然失忆了。
