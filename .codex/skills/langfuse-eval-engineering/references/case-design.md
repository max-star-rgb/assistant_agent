# Langfuse Case Design

只在用户已经选择 capability 后读取本参考。

## 场景契约

实现前先定义：

```text
Capability: 被测行为
Request: 发给 Agent 的具体请求
Environment: Agent 可见的信息、工具、身份和状态
Success: 能由独立证据观察到的成功结果
```

若不使用该能力也能通过、必要信息缺失或成功边界无法判断，则重做场景。

## 选择 Dataset 与 profile

完整读取 `evals/README.md`，从现有 Dataset 和执行 profile 中选择最窄、最安全且能够测到目标行为的
入口。不要在本参考中假设固定 Dataset 名称或命令；以当前代码和文档为准。

- scripted/mock 只验证评测闭环和确定性 wiring，不证明真实模型能力；
- 真实只读 profile 适合无工具克制、只读工具选择和回答忠实性；
- 真实系统 profile 适合多工具、媒体、生成和隔离写操作；
- system eval 只回答真实能力是否连通，不代替 Agent case。

优先扩展现有 Dataset。只有 capability、运行边界和结果权威都确实独立时才新增 Dataset。

## 选择独立证据

| 场景 | 独立证据 |
| --- | --- |
| 无工具请求 | 用户请求、可见工具、实际 Tool Trace、最终回答 |
| 检索或问答 | 固定或带版本的数据记录，以及支持/反驳关键结论的内容 |
| 工具选择 | 实际暴露工具、Validator 结果、工具参数、返回结果和最终回答 |
| 状态写入 | 初始状态、权限、最终状态、允许与禁止的变化 |
| 多轮约束 | 完整轮次输入、最终动作、状态和用户明确约束 |
| 媒体任务 | 指定媒体输入、Provider/Tool 证据和可独立检查的结果 |

历史 Agent 回答、工具调用摘要或目标自己生成的行动清单都不能作为真值。

## 设计依赖

逐项选择：

| 策略 | 使用条件 |
| --- | --- |
| live | 只读、低成本、稳定、获准使用凭据且难以复现 |
| frozen | 跨运行必须保持一致的数据或检索结果 |
| simulated | 写入、权限、故障或状态必须隔离并复位 |

通过现有接口替换依赖，不要把 Agent 决策搬到 fixture 或 adapter。为替代依赖定义输入输出 schema、
空结果、错误、超时、幂等、身份、权限、时间和状态变化。检索数据应包含相关项、干扰项、miss 和错误
ID；写操作应能观测并复位最终状态。

## 避免伪案例

- 不以改名字、改措辞或换 fixture 伪装新 capability；
- 不在请求中规定工具顺序，除非顺序本身就是被测契约；
- 不用 `required_tools` 代替语义判断“是否应该调用”；
- 不用精确措辞、回答长度、关键词或引用数量作为质量代理；
- 不让环境在 Agent 使用目标能力前直接泄露答案；
- 不把生产 Trace、Judge rubric 或隐藏证据放进 Agent 可见输入。
