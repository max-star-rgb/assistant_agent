# 核心不变量登记

下表是核心框架测试的稳定不变量登记。每个条目定义可观察的结构化契约，并指定负责守住该契约的
`tests/core/...` 测试文件。

| ID | 结构化契约 | 负责文件 |
| --- | --- | --- |
| POLICY-001 | 默认 pytest 收集范围仅为 `tests/core`；核心测试文件已登记，且不以完整人类文案或 feature implementation import 绑定行为。 | `tests/core/unit/test_test_policy.py` |
| BOOT-001 | mock/real provider mode 显式分离；离线启动不读取真实 Provider 配置且不会发起网络调用。 | `tests/core/integration/test_runtime_lifecycle.py` |
| RUN-001 | 生产 run 直接返回标准 messages；thread/run/checkpoint/interrupt/resume/cancel 与终态由 LangGraph Agent Server 所有，Graph state 不保存平行产品终态。 | `tests/core/integration/test_runtime_lifecycle.py` |
| LOOP-001 | 进程内复用唯一静态 `AssistantAgent`，不保留外层 wrapper graph；Memory lifecycle 由该 Agent 的官方 `before_agent/after_agent` middleware 接入。主 Agent 直接使用 Deep Agents 官方 loop、Todo、filesystem、task、summarization、HITL 与 `ToolNode`，不设置 model 或单 Tool run 累计次数上限；同一 model superstep 内同名 Tool 最多并行 12 次，并在 `recursion_limit` 耗尽前预留 8 个 step 生成无 Tool 的最终 `AIMessage`。本机主 Agent 与通用 worker 复用完整业务 Tool inventory、filesystem、`execute`、Skills、Tool Profile、HITL、Agent Home cwd 和 Agent Server OS identity；同步 task 预装 `general-purpose`、`coder`、`browser-operator`，异步 task 只提供与同步形态复用 worker graph 的 `general-purpose-background`。worker 不装配同步或异步 delegation，异步 task 只保存父子 thread/run correlation，不保存或传播 Workspace、仓库快照和文件副本。 | `tests/core/integration/test_runtime_lifecycle.py` |
| TOOL-001 | 生产进程内内建 Tool 均由官方 `@tool` factory 创建为标准 `BaseTool` 并经 `ToolNode` 执行；官方 `ToolRuntime` 注入直接隐藏模型 schema 中的 runtime-owned 参数，不存在动态生成的项目 schema 层，`ToolRuntime.server_info.user.identity` 注入受信身份；成功结果为标准 `ToolMessage(content, artifact)`，显式配置的预期失败与可重试 Tool 重试耗尽均成为有界 error `ToolMessage`，不终止生产 Graph。 | `tests/core/contract/test_tool_contract.py` |
| EXT-001 | 生产本地业务 Tool 由受信静态清单装配；MCP 使用官方 adapter、显式 allowlist、独立的 `general_purpose_tools` 安全重试名单、逐 Tool `interrupt_tools` 配置与确定性 namespace，二者都输出不携带项目 effect 分类的标准 `BaseTool`。业务 inventory 不重复实现或暴露文件、执行、Skill loader Tool；仓库文件能力只由 Agent 内的 Deep Agents `FilesystemMiddleware` 注入。 | `tests/core/contract/test_extension_contract.py` |
| MEMORY-001 | `enable_memory` 默认为 true；启用时每个顶层 chat run 在回答前通过单个 `before_agent` middleware recall 一次并冻结 `memory_context`，回答后由 `after_agent` middleware 通过官方 Agent Server SDK 在确定性 companion Memory thread 上 rollback 旧 pending Memory run，并立即 enqueue 新 delayed Memory run。Assistant 或单次 run 将其设为 false 时，recall 冻结为空且不调度 extraction。chat thread 不保留后台 pending run，extract 不在 chat run 内执行；recall 与 refresh 使用 LangChain 原生 Runnable retry，独立 extraction 使用 LangGraph `RetryPolicy`，均最多尝试三次，耗尽后对应 run 明确进入 error 而非静默 success。 | `tests/core/integration/test_memory_lifecycle.py` |
| CTX-001 | 生产上下文使用标准 messages；统一 Assistant 的 Prompt、冻结 Memory、Todo、task、summarization、retry、Tool Profile 和 HITL 均由官方 middleware 组装。main/worker 的原生 summarization 共享 `ProviderConfig` 的 context window、trigger/target ratio 与同一个启动期 token counter；real DeepSeek 缺 tokenizer 时启动失败关闭。正常 model call 预算耗尽前预留一次显式 `tool_choice="none"` 的无 Tool 模型调用。同步 task 预装 `general-purpose`、`coder` 与 `browser-operator`；`general-purpose` 输入只允许 description 对应的单条 message 与冻结 `memory_context`，输出只允许最终 message 和非空 structured response，空结果投影为明确失败。父 conversation、Memory status、Todo、Tool Profile、provider search profile、async task handle 与 worker transcript 均隔离，父 `async_tasks` 原样保留。角色实际授权只来自 composition 传入的 Tool、backend 与原生 `interrupt_on`；Tool metadata、description、Skill 和 Profile 不参与授权。filesystem/execute 与显式列入 `interrupt_on` 的 Tool 默认在 handler 前触发原生审批；Assistant 将 `require_tool_approval` 设为 false 时，原生 `when` 谓词跳过全部审批并直接执行；未列入的 Tool 按原生默认执行。 | `tests/core/integration/test_context_lifecycle.py`；`tests/core/integration/test_runtime_lifecycle.py` |
| GATE-001 | Agent Server 原生拥有生产 thread、run、queue、checkpoint、cancel 与 stream 生命周期；只注册 `assistant-native-v4`、`assistant-worker-v2`、`assistant-memory-v1` 三个 graph identity，不提供旧 alias。thread 只使用原生 `metadata.graph_id`，create/run 按该字段强制 owner，metadata update 禁止改写 graph identity；server-issued runtime facts 只在 create 写入且所有 identity 的 metadata update 均不可修改，普通 label/state update 与 owner-scoped interrupt/rollback 保持可用。run create 按 LangGraph 系统 Assistant UUID 区分当前 main/worker/Memory，明确拒绝 native-v1/v2/v3 与 worker-v1 系统 Assistant UUID，并允许已由 Agent Server 持久化约束的 v4 自建 Assistant UUID进入 main；普通 API 对 custom Assistant 的 read/search/run 按 owner 隔离，三个当前 system Assistant UUID 与 Studio 保持可见。worker 必须同时持有 `entry_profile=async_worker` 的严格 runtime metadata 和 async adapter 注入的进程内 internal permission；仅形状合法的普通外部 caller 必须拒绝，main/Memory 则拒绝 worker-only facts 和 capability。旧 run 的 interrupt/rollback 仍可按 owner drain/cancel，SDK adapter 拒绝 v1/v2/v3/unknown thread 与 checkpoint 进入 v4 run/resume/replay/stream。`/agent-service/v1` 只做媒体 wire 解析、原生资源关联和响应投影。 | `tests/core/contract/test_gateway_contract.py` |
| IDENT-001 | Agent Server `user.identity` 是生产运行的唯一用户身份；tokenless auth hook 在 mock/real 模式下都从客户端 `X-Assistant-User` 构造 identity，缺省为 `local-developer`。公开 `AssistantRunContext` 只有 `enable_memory` 与 `require_tool_approval`；identity、entry profile 与 media/visual capability 只经 Agent Server/runtime 的 namespaced metadata 注入。thread 的 namespaced runtime facts 创建后冻结，不能经 metadata update 改写；进程内 internal capability 只转换为 auth permission，不写入 state、thread metadata 或日志。assistant、graph、thread、run、媒体 connection 与 delivery ID 相互分离，同一 conversation 的 `thread_id` 在后续 run 间稳定。 | `tests/core/contract/test_gateway_contract.py`；`tests/core/integration/test_runtime_lifecycle.py`；`tests/core/integration/test_durable_lifecycle.py` |
| DUR-001 | Durable schedule、resume、cancel、background queue 与 failure atomicity 依照通用状态机转换；同一 store 上重建 service/worker 后，已登记 schedule 按时恢复且仅执行一次。 | `tests/core/integration/test_durable_lifecycle.py` |
| OBS-001 | 生产 compiled graph 通过 LangChain/LangGraph callback 与 LangSmith native tracing 暴露实际 Graph/Node/LLM/Tool 树；production composition 不重建 canonical 或 OTel shadow tree。 | `tests/core/contract/test_observability_contract.py` |
