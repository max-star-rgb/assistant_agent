# 核心不变量登记

下表是核心框架测试的稳定不变量登记。每个条目定义可观察的结构化契约，并指定负责守住该契约的
`tests/core/...` 测试文件。

| ID | 结构化契约 | 负责文件 |
| --- | --- | --- |
| POLICY-001 | 默认 pytest 收集范围仅为 `tests/core`；核心测试文件已登记，且不以完整人类文案或 feature implementation import 绑定行为。 | `tests/core/unit/test_test_policy.py` |
| BOOT-001 | mock/real provider mode 显式分离；离线启动不读取真实 Provider 配置且不会发起网络调用。 | `tests/core/integration/test_runtime_lifecycle.py` |
| RUN-001 | 生产 run 直接返回标准 messages；thread/run/checkpoint/interrupt/resume/cancel 与终态由 LangGraph Agent Server 所有，Graph state 不保存平行产品终态。 | `tests/core/integration/test_runtime_lifecycle.py` |
| LOOP-001 | 进程内复用唯一静态父 `AssistantRootGraph`；父图以合并 TrustedRuntimeFacts 采集的单个 `memory_recall` 作为每 run 回答前 checkpoint，再执行结构化 fast/planning/coding 路由与回答后的 Memory debounce refresh。fast 是共享的 `create_agent`；planning 也是官方 `create_agent`，只通过 `TodoListMiddleware` 获得 `write_todos`、通过 Deep Agents `SubAgentMiddleware` 获得真实 `task(description,subagent_type)` Tool，并把同一个 fast agent 注册为 `CompiledSubAgent`。一个或多个 task call 由内置 `ToolNode` 执行（独立调用可并行），子 Agent 的最终文本以原 tool call ID 对应的标准 `ToolMessage` 返回；生产不存在自研 controls、task 占位 schema、`Send(worker)`、join、Worker result ledger、budget 或 recovery loop。coding 是显式 StateGraph，repository 的并行分析配置公开默认关闭、显式启用时在首次 draft 前通过原生 `Send` 执行固定只读分析 fan-out并确定性 join，随后进入唯一顺序 mutation lane；批准的 patch 应用后执行确定性验证，formatter 增量 patch 返回同一 digest-bound approval/apply 闭环；eligible validation failure 最多两轮返回同一 digest-bound approval/apply/gates 闭环且不重跑已完成分析；final review 默认关闭，显式启用时在最终 validation 后冻结 schema/version-bound snapshot，通过原生 `Send` 并行执行固定只读 review、确定性 join canonical report，并在 integration 前进入独立 digest-bound decision；`unavailable` 不自动修复或跳过 decision，pending v1 与 v2 downgrade/mismatch fail closed，真正 completed v1 可 fresh-rebind；review decision 的 repair 分支只能先经 `consume_review_repair_budget -> consume_review_repair_context`，再进入 `inspect_and_draft` 或 terminal summarize，不存在 direct mutation shortcut；integration 关闭时 approve 形成 applied terminal，显式启用 integration 时只有 approve 才顺序执行受控 commit、merge preview 与 apply。 | `tests/core/integration/test_runtime_lifecycle.py` |
| TOOL-001 | 生产进程内内建 Tool 均由官方 `@tool` factory 创建为标准 `BaseTool` 并经 `ToolNode` 执行；官方 `ToolRuntime` 注入直接隐藏模型 schema 中的 runtime-owned 参数，不存在动态生成的项目 schema 层，`ToolRuntime.server_info.user.identity` 注入受信身份；成功结果为标准 `ToolMessage(content, artifact)`，非 read 预期失败与 read 重试耗尽均成为有界 error `ToolMessage`，不终止生产 Graph。 | `tests/core/contract/test_tool_contract.py` |
| EXT-001 | 生产本地 Tool 由受信静态清单装配；MCP 使用官方 adapter、显式 allowlist 与确定性 namespace，二者都输出标准 `BaseTool`。生产清单不暴露通用宿主文件读取 Tool，只暴露按 Skill ID 与已授权 reference ID 加载内容的窄只读 Tool。 | `tests/core/contract/test_extension_contract.py` |
| MEMORY-001 | 每个顶层 chat run 在回答前通过单个 `memory_recall` recall 一次，并在同一 checkpoint 冻结彼此独立的 `memory_context` 与 TrustedRuntimeFacts；recall 降级时 Memory 显式为空且 TrustedRuntimeFacts 仍可用。回答后通过官方 Agent Server SDK rollback 同 thread 旧的 pending Memory run并立即 enqueue 新的 delayed Memory run，pending chat run 不受影响，extract 不在 chat run 内执行。 | `tests/core/integration/test_memory_lifecycle.py` |
| CTX-001 | 生产上下文使用标准 messages；冻结 Memory 与 TrustedRuntimeFacts 保持独立 state 和 trust boundary，仅在最新真实用户请求前合并投影为一条分区明确的临时 `HumanMessage`，进入单次 fast 或 planning coordinator 模型请求且不写入对话 state；task 子 Agent 只获得模型生成的完整 description、冻结上下文、execution mode，以及 planner 已自主加载的 Skill ID/reference grant 映射，父 conversation、Todo、Tool Profile、调用计数和内部业务 Tool transcript 不跨 Agent 回灌，worker 的局部 Skill/Profile state 也不写回 planner。标准 `SKILL.md` 元数据由 Deep Agents `SkillsMiddleware` 渐进披露，正文只经窄 `load_skill` ToolMessage 进入当前角色的 run，Skill 不声明或授予 Tool。fast `create_agent` 由通用 `ToolProfileMiddleware` 提供 `activate_tool_profile`，只在当前 invocation 后续 model call 开放受信静态 profile 中的已注册 Tool；未归属 profile 的独立能力不受影响。Planner 可读取 Skill，但不持有 profile 激活或业务 Tool。Todo prompt/state/tool 由官方 `TodoListMiddleware` 所有；task schema、并行执行和 ToolMessage 结果回传由 Deep Agents 所有，项目只在 compiled worker 边界做 Skill state 的窄映射和结果投影。fast/planning 每个 invocation 最多 12 次模型调用，不设置全 Tool 总调用上限；每个 Tool 同一规范化参数最多执行一次、不同参数最多执行 12 次，Tool metadata 可声明更低的 per-Tool run limit。summarization、Tool retry 与 HITL 继续使用官方 middleware；fast 模式自动放行，planning task 内对非 read 业务 Tool 在执行前触发 HITL 并通过原生 checkpoint resume。coding patch 通过独立 approval/apply 节点执行 digest-bound 原生 HITL，coding merge 通过另一个绑定 frozen source/target/preview 的独立 HITL。 | `tests/core/integration/test_context_lifecycle.py`；`tests/core/integration/test_runtime_lifecycle.py` |
| GATE-001 | Agent Server 原生拥有生产 thread、run、queue、checkpoint、cancel 与 stream 生命周期；生产 graph ID 为 `assistant-native-v3`，不注册 v1/v2 alias；Agent Server auth 在 graph-aware thread create、显式 metadata identity update 与 chat run create 边界强制 owner + v3 identity，独立 Memory 保留自身 identity，旧 run 的 interrupt/rollback 仍可按 owner drain/cancel，SDK adapter 再复核；v1/v2/unknown thread 与 legacy checkpoint 只读，不能进入 v3 run/resume/replay/stream；`/agent-service/v1` 只做媒体 wire 解析、原生资源关联和响应投影，不拥有平行 Graph Runtime。 | `tests/core/contract/test_gateway_contract.py` |
| IDENT-001 | Agent Server `user.identity` 是生产运行的唯一用户身份；tokenless auth hook 在 mock/real 模式下都从客户端 `X-Assistant-User` 构造 identity，缺省为 `local-developer`；Assistant Runtime Context 只携带非身份入口能力、实时媒体模式与服务端 assistant execution preset，不复制用户或租户字段；assistant、graph、thread、run、媒体 connection 与 delivery ID 相互分离，同一 conversation 的 `thread_id` 在后续 run 间稳定。 | `tests/core/contract/test_gateway_contract.py`；`tests/core/integration/test_runtime_lifecycle.py`；`tests/core/integration/test_durable_lifecycle.py` |
| DUR-001 | Durable schedule、resume、cancel、background queue 与 failure atomicity 依照通用状态机转换；同一 store 上重建 service/worker 后，已登记 schedule 按时恢复且仅执行一次。 | `tests/core/integration/test_durable_lifecycle.py` |
| OBS-001 | 生产 compiled graph 通过 LangChain/LangGraph callback 与 LangSmith native tracing 暴露实际 Graph/Node/LLM/Tool 树；production composition 不重建 canonical 或 OTel shadow tree。 | `tests/core/contract/test_observability_contract.py` |

LOOP-001 final-review 补充约束：review 只能由默认关闭的 `CodingRepositoryConfig.code_review_enabled` 静态启用；validation、review input/result/report、HITL binding 与 commit 必须绑定同一 immutable-manifest v2 snapshot 的最终字节。所有五个 review read Tool 走 manifest-backed API；真实 reviewer 最多执行八次 read Tool，并保留第九次 model/ToolStrategy 调用生成结构化结果，未知 Tool 也计入同一总 ToolCall 预算；current v2 的 snapshot/tree/content/path/digest/permission/identity/expiry 错误 fail closed，普通稳定 reviewer failure 才可形成 `unavailable`；commit tree 的 content-address digest 必须等于 reviewed tree digest。validation failure、workspace-change、review-off terminal 与 commit comparison success/failure 都必须幂等释放不再需要的 snapshot lease，仍由后续 review/commit checkpoint 持有的 snapshot 不得提前释放。固定 current inventory 为 `correctness_regression`、`security_governance`、`tests_validation`，single mutation lane、integration default-off 与 snapshot-only reaper 不变。

LOOP-001 review-repair 补充约束只登记永久 core 可保护的公开拓扑：`coding_review_decision` 的 repair destination 为 `consume_review_repair_budget`，该节点只能进入 `consume_review_repair_context` 或 terminal summarize，context 节点只能进入 `inspect_and_draft` 或 terminal summarize；三者不存在直达 patch apply、validation、review 或 integration 的 mutation shortcut。findings-only、预算数值、context 消费、授权失效、完整重审、path inventory、snapshot lease 与 checkpoint lineage 属 owner authority 的当前运行时行为和可删除 Stage 5D TDD，不作为本 invariant 的永久保护声明。
