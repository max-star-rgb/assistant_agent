# 核心不变量登记

下表是核心框架测试的稳定不变量登记。每个条目定义可观察的结构化契约，并指定负责守住该契约的
`tests/core/...` 测试文件。

| ID | 结构化契约 | 负责文件 |
| --- | --- | --- |
| POLICY-001 | 默认 pytest 收集范围仅为 `tests/core`；核心测试文件已登记，且不以完整人类文案或 feature implementation import 绑定行为。 | `tests/core/unit/test_test_policy.py` |
| BOOT-001 | mock/real provider mode 显式分离；离线启动不读取真实 Provider 配置且不会发起网络调用。 | `tests/core/integration/test_runtime_lifecycle.py` |
| RUN-001 | 生产 run 直接返回标准 messages；thread/run/checkpoint/interrupt/resume/cancel 与终态由 LangGraph Agent Server 所有，Graph state 不保存平行产品终态。 | `tests/core/integration/test_runtime_lifecycle.py` |
| LOOP-001 | 进程内复用唯一静态父 `AssistantRootGraph`；父图直接执行每 run recall、结构化 fast/planning/coding 路由与回答后的 Memory debounce refresh。fast 是唯一共享的 `create_agent`；planning 是显式 `StateGraph`，普通 LLM Supervisor 通过标准 control ToolCall 或 `task(todo_id)` 决策，control 进入 `ToolNode`，一个或多个纯 task call 通过原生 `Send` 并行调用 scoped fast Worker，确定性 join 以原 tool call ID 写回标准 `ToolMessage` 后返回 Supervisor，无 ToolCall 直接结束；Todo 与 succeeded Worker result 单调保留，business blocked 作为数据，operational exception 原样交给 checkpoint/pending writes，恢复不重跑同 super-step 已成功分支；planning 不维护独立 Planner、Scheduler、Finalizer、admission、budget 或 recovery ledger。coding 是显式 StateGraph，repository 的并行分析配置公开默认关闭、显式启用时在首次 draft 前通过原生 `Send` 执行固定只读分析 fan-out并确定性 join，随后进入唯一顺序 mutation lane；批准的 patch 应用后执行确定性验证，formatter 增量 patch 返回同一 digest-bound approval/apply 闭环；eligible validation failure 最多两轮返回同一 digest-bound approval/apply/gates 闭环且不重跑已完成分析；final review 默认关闭，显式启用时在最终 validation 后冻结 schema/version-bound snapshot，通过原生 `Send` 并行执行固定只读 review、确定性 join canonical report，并在 integration 前进入独立 digest-bound decision；`unavailable` 不自动修复或跳过 decision，pending v1 与 v2 downgrade/mismatch fail closed，真正 completed v1 可 fresh-rebind；current findings 的 respond 只能经最多两轮的独立 `consume_review_repair_budget` checkpoint 与一次性 `consume_review_repair_context` 投影返回同一 mutation lane，旧授权全部失效且新 patch 必须完整重走 approval、validation、review 与 decision；integration 关闭时 approve 形成 applied terminal，显式启用 integration 时只有 approve 才顺序执行受控 commit、merge preview 与 apply。 | `tests/core/integration/test_runtime_lifecycle.py` |
| TOOL-001 | 生产进程内内建 Tool 均由官方 `@tool` factory 创建为标准 `BaseTool` 并经 `ToolNode` 执行；官方 `ToolRuntime` 注入直接隐藏模型 schema 中的 runtime-owned 参数，不存在动态生成的项目 schema 层，`ToolRuntime.server_info.user.identity` 注入受信身份；成功结果为标准 `ToolMessage(content, artifact)`，非 read 预期失败与 read 重试耗尽均成为有界 error `ToolMessage`，不终止生产 Graph。 | `tests/core/contract/test_tool_contract.py` |
| EXT-001 | 生产本地 Tool 由受信静态清单装配；MCP 使用官方 adapter、显式 allowlist 与确定性 namespace，二者都输出标准 `BaseTool`。 | `tests/core/contract/test_extension_contract.py` |
| MEMORY-001 | 每个顶层 chat run 在回答前 recall 一次并冻结 `memory_context`；回答后通过官方 Agent Server SDK rollback 同 thread 旧的 pending Memory run并立即 enqueue 新的 delayed Memory run，pending chat run 不受影响，extract 不在 chat run 内执行。 | `tests/core/integration/test_memory_lifecycle.py` |
| CTX-001 | 生产上下文使用标准 messages；冻结 Memory 仅作为最新真实用户请求前的临时 `HumanMessage` 进入单次 fast/Worker 模型请求，不写入对话 state；共享 fast/Worker `create_agent` 使用官方 model/tool call limit、metadata-driven per-Tool run limit、summarization、Tool retry 与 HITL middleware，fast 自动放行，planning Worker 对非 read 业务 Tool 在执行前触发 HITL。Supervisor 只投影 token-aware 有界父自然对话，并从有界受信上下文读取 Todo、Memory/TrustedRuntimeFacts、Skill/reference 与 Worker result；每个 Worker 只获得当前 Todo、必要 Skill/reference、冻结 Memory/TrustedRuntimeFacts 和私有 messages，内部业务 Tool transcript 不写回父 messages；只有 join 能标记 completed，pending 内容变化清除旧 blocked result，completed Todo 与 succeeded result 不得被后续 write/retry 覆盖，approve/resume 与 operational pending-writes 恢复不重放已完成执行。coding patch 通过独立 approval/apply 节点执行 digest-bound 原生 HITL，coding merge 通过另一个绑定 frozen source/target/preview 的独立 HITL。 | `tests/core/integration/test_context_lifecycle.py`；`tests/core/integration/test_runtime_lifecycle.py` |
| GATE-001 | Agent Server 原生拥有生产 thread、run、queue、checkpoint、cancel 与 stream 生命周期；生产 graph ID 为 `assistant-native-v3`，不注册 v1/v2 alias；Agent Server auth 在 graph-aware thread create、显式 metadata identity update 与 chat run create 边界强制 owner + v3 identity，独立 Memory 保留自身 identity，旧 run 的 interrupt/rollback 仍可按 owner drain/cancel，SDK adapter 再复核；v1/v2/unknown thread 与 legacy checkpoint 只读，不能进入 v3 run/resume/replay/stream；`/agent-service/v1` 只做媒体 wire 解析、原生资源关联和响应投影，不拥有平行 Graph Runtime。 | `tests/core/contract/test_gateway_contract.py` |
| IDENT-001 | Agent Server `user.identity` 是生产运行的唯一用户身份；tokenless auth hook 在 mock/real 模式下都从客户端 `X-Assistant-User` 构造 identity，缺省为 `local-developer`；Assistant Runtime Context 只携带非身份入口能力、实时媒体模式与服务端 assistant execution preset，不复制用户或租户字段；assistant、graph、thread、run、媒体 connection 与 delivery ID 相互分离，同一 conversation 的 `thread_id` 在后续 run 间稳定。 | `tests/core/contract/test_gateway_contract.py`；`tests/core/integration/test_runtime_lifecycle.py`；`tests/core/integration/test_durable_lifecycle.py` |
| DUR-001 | Durable schedule、resume、cancel、background queue 与 failure atomicity 依照通用状态机转换；同一 store 上重建 service/worker 后，已登记 schedule 按时恢复且仅执行一次。 | `tests/core/integration/test_durable_lifecycle.py` |
| OBS-001 | 生产 compiled graph 通过 LangChain/LangGraph callback 与 LangSmith native tracing 暴露实际 Graph/Node/LLM/Tool 树；production composition 不重建 canonical 或 OTel shadow tree。 | `tests/core/contract/test_observability_contract.py` |

LOOP-001 final-review 补充约束：review 只能由默认关闭的 `CodingRepositoryConfig.code_review_enabled` 静态启用；validation、review input/result/report、HITL binding 与 commit 必须绑定同一 immutable-manifest v2 snapshot 的最终字节。所有五个 review read Tool 走 manifest-backed API；真实 reviewer 最多执行八次 read Tool，并保留第九次 model/ToolStrategy 调用生成结构化结果，未知 Tool 也计入同一总 ToolCall 预算；current v2 的 snapshot/tree/content/path/digest/permission/identity/expiry 错误 fail closed，普通稳定 reviewer failure 才可形成 `unavailable`；commit tree 的 content-address digest 必须等于 reviewed tree digest。validation failure、workspace-change、review-off terminal 与 commit comparison success/failure 都必须幂等释放不再需要的 snapshot lease，仍由后续 review/commit checkpoint 持有的 snapshot 不得提前释放。固定 current inventory 为 `correctness_regression`、`security_governance`、`tests_validation`，single mutation lane、integration default-off 与 snapshot-only reaper 不变。

LOOP-001 review-repair 补充约束：`respond` 仅对 current `findings` report 合法，规范化 response 与最多 12 条 findings 摘要只在独立的最多两轮 review-repair budget checkpoint 后一次性投影给既有 inspect/draft；该预算不与 validation repair budget 合并或互相重置。接受 respond 必须原子清除上一轮 patch、validation、review 与 integration authorization，并幂等释放不再需要的 snapshot lease；释放失败只进入既有 owner reaper 的 `cleanup_pending`。后续 patch 必须重新 approval、apply、validation、final snapshot、只读 review 与 decision，累计 path inventory 在 mutation 前后按受信 workspace 和当前批准 proposal 安全收敛。START/resume/non-terminal checkpoint 对 count/history lineage、context consumption、互斥授权以及 workspace/digest/schema/path/identity/permission drift fail closed；reviewer 始终只读。
